# 1.0 正式发行的本地准备

这是在冻结898之后的隔离维护工作，不修改原受限版签收、原分支/标签或0501安装包。此目录中的新文件是配置合同与待填模板，不能当作正式分发包或真实运行资格。

## 发行渠道与功能范围分开

- 不设置 `DOMESTIC_RELEASE_DISTRIBUTION_CHANNEL` 时，保留原 `restricted_instance` 行为。
- 正式服务器显式使用 `DOMESTIC_RELEASE_DISTRIBUTION_CHANNEL=app_store`、`DOMESTIC_RELEASE_CAPABILITY_PROFILE=core_translation`。
- 正式核心仍延期购买、PSTN、Agent、Egress及公众Call Link；账号投递、告警和发布材料不再跟随这些功能延期。
- `API_BASE_URL` 必须是公网HTTPS，`REALTIME_WS_ENDPOINT`必须是公网WSS，不能带用户凭据、query或fragment。该校验只确认语法/明显保留地址，不替代DNS、TLS、域名所有权、服务容量和实际可用性核验。
- 模型HTTP地址继续按原私有服务边界使用，不将ASR/MT/TTS端口直接暴露公网，也不换成1.1的模型组合。
- 正式前端使用 `WUJIE_DISTRIBUTION_CHANNEL=app_store`、`WUJIE_PRODUCT_PROFILE=core_translation`。构建脚本同时传入Dart与原生身份，并按 `WUJIE_INFO_PLIST_SUFFIX=-Formal` 选择禁止内测明文放行的plist。

## 首发范围与数据保护

`formal-release-scope.json`列明计划范围。正式1.0为中英在线核心；现有扫描和历史保留。新原生包、真实模型资格、十人并发和设备验收均尚未取得。

正式配置不能通过旧设置重新打开端侧、未签收语种或我的声音模式。界面仍复用既有页面，延期选项不可误触。旧设置保留，不自动覆盖；若不适用则明确提示，再由用户选择支持的设置。私有渠道不受这些正式限制影响。

通话Tab保留，输入并朗读继续保留；公众发起/加入通话在正式渠道标明未开放。服务器阻止对应新建/入房及购买、声纹/声音录入等延期操作，历史和必要结束/删除接口不因延期被整体移除。后续开启这些能力需要新的资格和明确范围，不以隐藏按钮代替服务端保护。

生产环境禁止测试账号回退；存储中的凭据到期时间无效或已到边界时拒绝使用。注销申请仍如实称“申请”，不把请求成功冒充法定数据销毁已经完成。真实注销/保留规则与外部账号通道仍需后续验收。

## 正式会话的停止与结算

复用原会话、内部事件同步、`settle:<sessionId>`唯一账本和移动端 finalization outbox，不新增平行账本。正式新会话在原记录中保存登录会话哈希；模型准备前先向 API 核验登录仍有效并申请首次准入。已结束或已准入的会话不能用同一旧凭据再次新开流；退出、到期和注销申请使后续核验失败，运行中的既有 30 秒心跳据此结束本连接。该边界不是硬件防复制证明。

只有实时适配层关闭成功后，网关才签发用途隔离的 `wj10stop` 回执，绑定用户、会话及服务端计时。API 验证回执后才使用其中秒数，忽略客户端申报；内部停止同步和客户端持久化重传共用原结算事务。回执只能证明已发生的停止，不能启动推理、增加额度或延长授权；为支持迟到结算，不将它当作短期使用凭据。它不证明远端 GPU 尾部工作和供应商账单已全部终止，后者需要真实故障验收。

尚未准入且具有新正式登录绑定的 created 记录，可以在同一会话锁内安全按零结束；配对的新网关必须在请求模型前将其改为 active，因此后续准入会被拒绝。没有新正式绑定的旧记录不套用此零结算例外。签名秘密只在原 API/网关服务端配置中，正式渠道至少 32 字符，P1 没有创建或变更真实密钥。

关闭失败、API 准入结果不明或停止凭据缺失时，不能发出假 ended 回执，不能仅靠心跳超时结算。只有新正式会话的预占带 `realtime_session_hold:gateway_stop_v1` 标记，过期后仍计入预占直到可信结算；旧记录 TTL 规则不追改，也不释放现有 1.1 的 445 秒或 unknown。新增字段复用 JSON/PG payload，无新增表结构迁移。

API、Gateway 和 App 必须作为同一协议候选分阶段部署，不能让旧网关绕过新准入逻辑。当前离线证据针对既有单 API/单网关协调路径；多副本竞争、进程彻底丢失、真实依赖关流及告警人工恢复尚未取得生产资格。回滚不得将持有未结正式会话的数据直接交给旧受限版清理器。

## 材料模板刻意不能通过

`formal-release-materials.example.json`中未知项为空或false，没有虚构备案号、邮箱、正式签名、审核就绪或许可。正式免费iOS材料不要求已延期Android截图或退款政策；但必须显式指定iOS和关闭购买，且不能使用开发期获准的占位备案号。

原私有文档中的主体/域名基线不是对新生产资格的在线核实。若确认要改用其他正式身份/域名，需先审阅影响并更新绑定；不能用模板直接覆盖运行配置。这里不保存任何真实密钥。

可在本地运行纯材料检查，预期返回not_ready：

```sh
DOMESTIC_RELEASE_DISTRIBUTION_CHANNEL=app_store npm run check:domestic-release-materials -- --file release/private/1.0.0/formal-release-materials.example.json --json
node scripts/check_mobile_app_release_readiness.mjs --platform ios --distribution-channel app_store --json
```

这两条是本地文件校验。`check:domestic-release-ready`的完整模式可能请求实际API、模型和运维接口，P1不在无预算授权下执行它；P1使用注入的模拟接口和离线网络阻断验证其行为。

## 后续步骤

P1只提供源码和HOST证据。P2另行固定实际发行输入并准备原生候选；没有正式profile时不得把开发签名包改名晋级。P3部署/迁移、P4安装/真实模型与设备资格、P5提交/发布均需对应明确批准。

正式输入仍包括：Apple身份/分发签名、生产域名及端点、账号投递、告警、真实备案/隐私/SDK与模型声音许可、独立备份和恢复方案。真实测试需单独确认账号分钟、资源窗口和费用；不套用过期的1.1授权，不充值、授额或自动续窗。

十人低延迟目标保留。P1模拟通过不能证明模型质量、物理声音、十路持续推理P95、功耗或温控。每个层级的结果和未验证项必须分别交付。
