# 原Gateway断开检查点与代际接管（第87批）

复用原finalizer、PublicSessionEventSink、API runtime/admission查询和session-manager，不新建模型、连接管理服务或账本。

## 当前默认断开路径

停止接受音频并排空已接收内容 → 原sink写入disconnected并回读可信检查点 → 在原session map绑定连接代际 → 原结束/唯一结算 → 关闭模型与清理连接。

因此，当前默认策略仍不是等待新WebSocket续接。检查点的落盘与回读已在原loopback链验证，但不会因此让模型长时间驻留。若恢复窗口/额度不足，仅拒绝恢复资格，正常结束仍由原可信停止与结算规则处理；不能以恢复拒绝代替退款或零费用结算。

## 同进程接管基础

原attachSession的公有恢复参数要求expectedGeneration和新近核验的API recovery回执。只有原会话仍存在、claims一致、当前代际和已保存检查点精确匹配、窗口/Token有效时，才可同步递增代际一次。不得通过恢复调用创建新会话，旧代际/重复调用/不同水位被拒绝。

接管完成仅更新原内存代际，确认连接后仍处于paused；不自动激活模型、音频或TTS。旧清理异步返回时重新核对代际，不能关掉或删除新代际会话。私有原路径不变。

这不是跨Gateway或数据库的原子所有权协议，也不是API查询与本地接管间的分布式事务。当前新公有WebSocket恢复入口仍关闭，不允许绕过Provider状态、确认sink序列和手机音频序号衔接来调用接管函数。
