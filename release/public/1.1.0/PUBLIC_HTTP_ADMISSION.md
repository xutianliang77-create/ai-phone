# 原HTTP协调与Gateway当前授权查询（第79批）

本批接回原API，不新增App或模型中台。本地模型分工不变；在线ASR/翻译/开启的TTS仍为公共。以下是代码接口及合成验证范围，不是生产启用说明。

## 原创建入口

`POST /realtime/sessions`沿用原账号认证和请求校验。只有启动代码明确向buildApp提供publicRealtimeAuthority时，online请求才进入新增协调分支。默认buildApp()、普通环境配置、手机请求和模型配置页都不能自行安装或启用该权威来源，默认仍拒绝公有创建。

该分支要求HTTPS或可信loopback，以及8–128字符的Idempotency-Key。服务器按部署、认证账号和请求键计算稳定sessionId，原规范化请求摘要负责同键异内容冲突；原始请求键不落库。相同键的并发/重建后重试复用会话和hold，不变成新收费会话；新操作需新键。手机请求键的完整生命周期接入仍待后续客户端联验。

协调器复用第78批准备/发行函数：准备原会话 → 可信来源解析独立核验的同意/预算/资格 → 先验证完整回执集合 → 原回执/admission持久化 → 原lease/hold/签名发行。HTTP body不能携带自授资格、owner、Token绑定或采样率。结果同步授权仍独立，不因创建或查询自动获得。

publicRealtimeAuthority必须按sessionId幂等解析真实已核验回执，处理取消和不确定的外部预算结果；本批未安装任何真实生产来源。回调超时和取消会阻止本协调器后续写入/返回Token，但不能保证不合作的外部实现没有副作用，外部结果必须另行对账。已提交或不确定的原会话/hold留待同键重试，不自动清空或新建替代会话。

## 删除后的请求重放

原快照增加可选publicCreationBindings，仅保存服务器HTTP会话ID到请求摘要的映射，不保存正文、原请求键、Token或密钥。该映射与准备记录同事务写入，失败一起回滚；旧快照无该字段仍兼容，损坏字段拒绝加载而不是清空。

删除会话不移除这个最小请求占用记录，旧键不能重新创建已删除会话。请求摘要保留期、实际部署数据恢复和旧版本降级兼容需纳入发行策略，不能用旧程序丢弃该字段后继续公共写入。本批未迁移或删除用户数据。

PostgreSQL尚未具备此新增持久请求占用路径，因此本HTTP协调分支对PostgreSQL明确返回not_ready，不能把进程内锁宣称为分布式幂等。其他原私有/内部仓库调用不因本分支改换数据库。后续沿原数据库仓库补齐，不建设独立存储系统。

## 当前授权查询

`POST /internal/realtime/sessions/:sessionId/admission`使用原内部鉴权，要求安全传输，返回no-store。输入仅含会话/用户/部署、grant/lease/capture/语言策略、配置版本/hash/采样率、用途及每次随机requestId；不发送签名Token、音频、正文或模型凭据。

API只读检查当前记录、有效的同意/预算/资格、已发行绑定、当前配置和lease期限。connect仅允许尚未开始且Token未过期的created会话；dispatch仅允许活动证据新鲜、非uncertain且未超过额度时长的active会话。暂停/断开恢复不是dispatch，不能借查询自动续期或恢复会话。独立的结果同步许可变化不混同为推理许可变化。

返回仅为同一请求的授权元数据和期限，不回传模型配置或任何秘密，不更新活动、采样水位或账本。Gateway复用原API事件sink传输，校验全字段和随机requestId，拒绝缓存/串会话/过期/超大/畸形回执；超时覆盖网络和响应体，不自动重试。有效回执不能长期缓存为模型许可，实际发送前仍有原model-attempt写入校验。
