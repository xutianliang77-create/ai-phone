## 1. 产品定位

国内版 App 是一款面向中国大陆用户的 AI 实时通讯翻译产品，首发聚焦中英互译，并逐步扩展到 Hy-MT2 支持的多语言翻译能力。

核心使用场景：

- 面对面中英实时同声传译。
- 会议、课堂、讲座 Listening Mode。
- 输入姓名、地址、数字、产品型号后翻译并朗读。
- 通过 Call Link 发起免安装翻译通话。
- 拨打手机号翻译电话和 AI Calling Agent 灰度。
- 图片、相机、截图 OCR 翻译。
- 保存历史、全文、摘要、重点、术语和导出。
- 使用 LLM 对 ASR final 文本做可追溯优化，并对会议纪要、通话记录和 Agent 结果做结构化整理。

核心承诺：

- 中文界面优先，国内网络可用。
- 默认支持中文说话翻英文、英文说话翻中文。
- 端侧模式弱网可用，在线模式使用国内自托管模型链路。
- 通话和记录链路要保存字幕、译文、时长、用量和诊断信息。
- 不宣传直接拦截系统电话、微信或第三方 App 原生通话音频。

## 5. 全局功能规则

### 5.1 端侧 / 在线模式

同传页必须提供显式处理模式开关：

- 端侧：iOS 使用 CoreML Nemotron ASR + iOS 系统翻译 + 系统 TTS；Android 使用系统 SpeechRecognizer ASR 兜底。
- 在线：音频帧进入 Realtime Gateway，服务端使用 Qwen3-ASR-0.6B original tuned v3 + Hy-MT2-1.8B + VoxCPM2。

切换规则：

- 未开始或已结束时允许切换。
- 同传中不允许切换，并显示“同传中不可切换设置”。
- 在线链路失败后显示“重试在线”和“切回端侧”。
- 端侧不可用时提示进入模型链路诊断，不自动切到在线。
- 端侧模式默认不扣实时同传分钟；在线模式、Call Link、PSTN 和 Agent 按服务端权威时长或 credits 计费。

架构说明：外部技术设计评审稿中的 sherpa-onnx 双端统一 ASR、Go 微服务和完整平台化数据栈只作为目标架构 TODO；当前 P0/P1 不替换 iOS CoreML/Nemotron、Android 系统 ASR 兜底和 Qwen3-ASR-0.6B original tuned v3 + Hy-MT2-1.8B + VoxCPM2 在线主链路。

### 5.2 语言设置

源语言选项：

- 自动识别。
- Hy-MT2 支持语言：中文、英语、法语、葡萄牙语、西班牙语、日语、土耳其语、俄语、阿拉伯语、韩语、泰语、意大利语、德语、越南语、马来语、印尼语、菲律宾语、印地语、繁体中文、波兰语、捷克语、荷兰语、高棉语、缅甸语、波斯语、古吉拉特语、乌尔都语、泰卢固语、马拉地语、希伯来语、孟加拉语、泰米尔语、乌克兰语、藏语、哈萨克语、蒙古语、维吾尔语、粤语。

目标语言选项：

- 自动反向。
- 同上 Hy-MT2 支持语言。

规则：

- 默认源语言为自动识别，目标语言为自动反向。
- 当源语言和目标语言相同时，不能创建在线会话。
- 中英首发体验必须优先优化，其他语言先作为灰度能力。
- ASR 返回语言和置信度时，记录到字幕和历史诊断。
- 低置信度时保留字幕并记录诊断，不静默用目标语言反推源语言。

### 5.3 权限

- 麦克风：仅点击开始同传、进入通话、加入房间时请求。
- 相机：仅进入拍照扫描时请求。
- 相册：仅选择相册导入时请求。
- 通知：仅用户开启通话提醒或 Agent 结果提醒时请求。

### 5.4 隐私和数据

- 默认不保存原始音频。
- 保存原文、译文、时间戳、语言、provider、model、latency、failure reason。
- 电话和 AI Agent 必须保存用户授权、提示文案版本和执行状态。
- 日志中手机号、地址、API Key、token 必须脱敏。
- 实时协议、用量结算、历史生命周期和删除导出边界以 `docs/domestic-realtime-billing-data-design.md` 为准。

### 5.5 错误恢复

所有核心链路错误必须给出中文解释和下一步动作：

- 麦克风未授权：去设置授权。
- 端侧模型未加载：打开模型链路诊断。
- 在线 ASR 失败：重试在线或切回端侧。
- 翻译失败：重试翻译或保存原文。
- TTS 失败：保留字幕，提示语音播放失败。
- 网络断开：自动重连或显示重新进入。
- 余额不足：进入套餐和 credits 页面。

### 5.6 账号、首启和合规准入

- P0 端侧同传允许游客试用，但触发在线同传、Call Link、PSTN、AI Agent、支付和云同步前必须登录。
- 国内版默认以手机号验证码登录为主，实名边界、注销和个人信息副本导出由 `docs/domestic-account-identity-compliance-design.md` 承载。
- App 首次启动必须先展示用户协议和隐私政策，同意前不得初始化非必要第三方 SDK；当前 App 已接入首启同意门禁、账号页、手机号验证码开发登录、退出、个人信息导出和注销请求。
- 首次使用在线同传、通话、Agent 或云端语音处理前，必须单独告知语音属于敏感个人信息，并取得单独同意；当前在线同传、Call Link 和 AI Agent 已接入基础单独同意弹窗。
- 游客边界服务端强制和账号发布安全门禁已基础接入；发布前仍需继续完成真实短信商户/模板/回执联调、登录态失效联动、SDK 延迟初始化实测和真机验收。
- 用户撤回同意后，相关云端能力不可继续使用，但端侧同传仍可按本地能力保留。

### 5.7 LLM 文本优化和记录整理

- LLM 文本优化只处理 final 字幕或会后记录，不覆盖原始 ASR。
- 实时同传展示可使用优化文本，但 segment 详情和历史必须保留 `rawText`、`optimizedText` 和 `translatedText`。
- 端侧模式默认不上传 ASR 文本；用户登录、开启云端智能优化并完成语音敏感信息单独同意后，才允许将 final 文本发给 LLM。
- 会议纪要、通信记录和 Agent 任务结果由 LLM 生成结构化 review，必须包含 provider、model、promptVersion 和来源 segment。
- 总体规则以 `docs/llm-asr-refinement-and-record-review-functional-design.md` 为准；ASR 优化细节以 `docs/llm-asr-refinement-functional-design.md` 为准；记录整理细节以 `docs/llm-record-review-functional-design.md` 为准。

## 6. 同传模块

### 6.1 面对面模式

用户目标：两个人面对面，各说各的语言，App 自动识别并翻译。

主流程：

1. 用户选择“对话”。
2. 设置端侧或在线、源语言和目标语言；实时同传自动朗读在 iOS 连续 ASR 稳定方案完成前暂不开放。
3. 点击“开始”。
4. App 请求麦克风权限。
5. 实时显示原文和译文。
6. 可暂停、恢复、结束。
7. 结束后保存历史。

字幕规则：

- 原文使用大字号。
- 译文使用次级颜色。
- 每段包含 sourceText、translatedText、sourceLanguage、targetLanguage、provider、model。
- `<sil>`、`[noise]`、`[blank]`、`[unk]` 等静音噪声标记不得展示、保存或朗读。
- 字幕超过一屏后自动滚动到最新。
- 最后一段标记为当前句；译文尚未 final 时显示翻译 pending，不能用空白区域冒充已完成。
- 用户手动上滑查看旧内容时停止自动跟随，并显示“回到底部”入口；点击后恢复跟随最新字幕。
- 自动朗读默认关闭；采集、系统 TTS 和在线 PCM 必须共用 AudioSessionCoordinator，平台中断后恢复当前采集源。
- 扬声器、听筒和未知输出路由在译文播放期间及 350ms 尾音窗抑制采集；有线和蓝牙耳机不关闭采集，支持双方重叠说话。
- 连续 20 句、扬声器和耳机真机验收通过后，才允许调整默认开关。

端点和 flush：

- 说完后必须 flush 最后一段。
- 不能出现最终历史里“有原文无译文”的正常段落。
- 在线链路 flush 失败时保留原文并展示错误。

验收标准：

- 3 秒内出现识别反馈。
- 常规译文 1-3 秒内出现。
- 中英快速切换不连续漏译。
- 连续 6-10 句字幕和翻译不中断；自动朗读重新开放前不得影响连续 ASR。
- End 后历史详情可打开。

### 6.2 Listening Mode

用户目标：听课、演讲、会议时只看字幕和翻译，不打扰现场。

差异规则：

- 强制关闭实时同传自动朗读；进入 Listening 时不覆盖用户的对话声音偏好，切回对话后恢复原选择。Type-to-Speak 和通话译音轨仍可独立播放。
- 字幕字号更大。
- 支持标记重点。
- 结束文案为“结束并总结”。
- 会后优先生成摘要、重点和待办。

场景标签：

- 会议。
- 课堂。
- 讲座。
- 客服。
- 医疗陪同。
- 外贸沟通。

### 6.3 Type-to-Speak

用户目标：输入难识别内容，让系统翻译并朗读。

入口：

- 同传页。
- 通话中页面。
- 记录详情里的“再次播放”。

主流程：

1. 输入原文。
2. 选择目标语言。
3. 点击翻译。
4. 展示译文。
5. 点击朗读或播放给对方。
6. 保存为历史 segment，标记 `source=typed`。

特殊规则：

- 姓名、地址、电话号码、金额、产品型号朗读时要可读化。
- 可读化只影响 TTS 文本，不改写屏幕译文。
- 通话中播放 Type-to-Speak 时，应避免本端麦克风把 TTS 再识别。

## 7. 通话模块

### 7.1 通话首页

入口卡片：

- 发起翻译通话。
- 拨打手机号。
- AI 帮我打电话。
- 加入通话链接。

首页展示：

- 剩余分钟或 credits。
- 最近通话。
- 灰度功能状态。
- 通话合规提示入口。

### 7.2 Call Link 翻译通话

用户目标：发起一个翻译通话链接，对方通过浏览器免安装加入。

角色：

- Host：App 用户。
- Guest：Web 或 App 加入者。
- Worker：服务端翻译参与者。

创建流程：

1. Host 选择双方语言。
2. 点击生成链接。
3. API 创建 callId、sessionId 和 LiveKit room。
4. Host 获取 room token 并入房。
5. Host 通过微信、短信或复制链接发给 Guest。
6. Guest 点击链接进入 Web 入房页。
7. Worker 订阅双方音频，发布字幕、译文和 TTS 音轨。

Web Guest 兼容性规则：

- 入房页必须检测 `getUserMedia`、音频播放、LiveKit SDK 和网络连通性。
- 微信内置浏览器不支持或体验不稳定时，必须引导用户用系统浏览器打开或下载 App。
- 当前 Web Guest 已实现微信提示、复制通话链接、仅字幕降级、能力诊断和点击加入时音频解锁；发布前仍需微信/Safari/Chrome/Android 真机矩阵验收。
- Guest 入房前必须看到录音、转写、AI 翻译和隐私处理提示。
- Web 页脚正式发布时必须展示真实 ICP/App 备案相关信息。

通话中显示：

- 我/对方角色标签。
- 原文。
- 译文。
- TTS 就绪状态。
- Worker 状态：ASR、翻译、TTS、网络、可重试。
- 通话时长和用量。

音频规则：

- Host 和 Guest 发布普通麦克风轨。
- Worker 发布 `translation-tts-host-*` 和 `translation-tts-guest-*` 译音轨。
- Host 只播放发给 host 的译音轨，Guest 只播放发给 guest 的译音轨。
- Worker 不得订阅自己发布的 TTS 译音轨进入 ASR。

结束流程：

1. Host 点击“结束并保存”。
2. API 幂等结束 call session。
3. 计算 consumedSeconds。
4. 扣减用量。
5. 保存全文、译文、摘要、重点。

异常：

- Guest 未授权麦克风：提示重新授权。
- Worker 未入房：显示字幕服务未就绪。
- TTS 失败：保留字幕并提示语音失败。
- 网络断开：自动重连或提示重新进入。
- 重复结束：不能重复扣费。

### 7.3 拨打手机号翻译电话

用户目标：用户在 App 内发起 VoIP，另一方接普通电话。

灰度状态：

- P2 灰度功能。
- 未配置 PSTN 服务商时入口隐藏或显示“灰度中”。

主流程：

1. 输入对方手机号。
2. 选择我的语言和对方语言。
3. 展示费用预估、录音/转写/AI 翻译提示。
4. 用户确认拨打。
5. 服务端通过 PSTN/VoIP provider 呼叫对方。
6. App 进入通话等待页。
7. 对方接听后开始双向 ASR、翻译、TTS。
8. 结束后生成记录和用量账单。

被叫告知规则：

- 接通后必须用被叫方语言说明“本通话由 AI 或翻译服务协助，并会进行转写和实时翻译”。
- 被叫拒绝或未确认继续时，必须终止通话且不得重拨。
- 被叫告知、拒绝、继续、结束等状态必须留痕。

状态：

- 未配置服务商。
- 余额不足。
- 正在拨号。
- 等待接听。
- 已接通。
- 对方忙线。
- 无人接听。
- 失败退款。
- 已结束。

### 7.4 AI Calling Agent

用户目标：让 AI 代打电话，例如预约、咨询、联系客服。

任务类型：

- 预约。
- 查询。
- 取消或改期。
- 客服沟通。
- 自定义任务。

主流程：

1. 用户填写任务目标、对方电话、语言、时间偏好和个人信息。
2. AI 生成话术草稿。
3. 用户确认授权。
4. Worker 拉取授权任务。
5. PSTN Bridge 发起电话或返回未配置错误。
6. Worker 回写状态。
7. 用户查看结果摘要、失败原因和下一步。

安全限制：

- 拨打前必须确认授权。
- 接通后必须主动表明 AI 身份，不能冒充真人或机构。
- 付款、合同、医疗、法律、身份验证必须请求用户接管。
- 不允许冒充政府、银行、医院或他人身份。
- 所有授权、任务目标、状态回写和失败原因必须保存。

## 8. 扫描翻译模块

入口：

- 拍照。
- 相册。
- 截图导入。

流程：

1. 用户选择图片来源。
2. App 获取权限。
3. iOS 使用 Vision OCR，Android 使用 ML Kit OCR。
4. 展示识别原文。
5. 翻译为目标语言。
6. 展示原文、译文、对照视图。
7. 用户复制、保存或分享。

验收素材：

- 菜单 10 张。
- 外贸合同和报价单 10 张。
- 物流和报关单据 10 张。
- 路牌和说明 10 张。

异常：

- 相机未授权。
- 图片无法读取。
- OCR 置信度低。
- 翻译服务不可用。
- 保存失败。

规则：

- 翻译失败时仍允许保存 OCR 原文。
- OCR 保存不消耗实时同传分钟。
- 记录中标记 provider、confidence 和 latency。

## 12. 模型链路和诊断

诊断页展示：

- API health。

- TTS endpoint、provider、model。

诊断操作：

- 检查服务。

## 13. 合规和安全

必须明确提示：

- AI 翻译可能不完全准确。
- 电话、通话和 Agent 场景涉及转写和 AI 处理。
- 用户可删除历史记录。
- 默认不保存原始音频。

AI Agent 和电话：

- 拨打前展示录音、转写、AI 翻译提示。
- 保存用户授权。
- 支持人工接管。
- 高风险场景禁止自动完成决策。

日志安全：

- API Key、LiveKit token、手机号、地址脱敏。
- 内部接口需要强 `INTERNAL_API_SECRET`。
- Worker 事件接口和 room token 接口不得公开调用。

## 15. 非目标和边界

首发不做：

- 直接监听系统电话音频。
- 直接拦截微信、WhatsApp、Telegram、LINE 原生通话音频。
- 未授权自定义语音克隆。
- 把海外 AI 服务作为国内版主链路。
- 无服务商合规评审的中国大陆 PSTN 商用发布。

允许作为灰度或研究：

- 视频 Call Link。
- 自定义语音。
- 多语言深度优化。
- 企业术语库和团队后台。
- 社交 App 分享链接模板。
