# 无界AI企业版隐私与数据处理说明

状态：未批准的隐私和数据处理模板，不构成法律意见

## 1. 角色和目的

正式合同需逐区域确定客户与平台的数据控制者/处理者角色。平台只为企业会议、客服和
经批准的营销目的处理必要数据，不得将客户正文、音频、声纹或联系人默认用于模型训练。

## 2. 数据分类

- L1：账号、租户、成员、角色、套餐和系统配置。
- L2：会议、客服、营销业务元数据及会话索引。
- L3：字幕、译文、知识、客户资料、录音和屏幕 OCR 文本。
- L4：凭据、签名密钥、支付/身份验证材料和受限监管数据。

L3/L4 使用最小化、加密、区域限制、purpose-specific authorization、保存期限和删除流程。
原始屏幕帧不落业务数据库；日志、trace 和错误响应不得包含客户正文或凭据。

## 3. 授权与营销合规

声纹、录音和诊断音频分别取得独立授权；撤回或过期后阻断新副作用并进入生命周期清理。
营销外呼还必须通过号码授权、tenant/global 禁拨、国家策略、当地时间窗口、AI 身份告知、
审批快照和人工接管门禁。适用国家规则必须由企业合规负责人和法务逐版本批准。

## 4. 数据驻留和分处理方

每个租户绑定 home region 和 Cell。正式发布包应列出实际启用的云、LiveKit、PSTN、模型、
CRM、日历、对象存储、监控和支持分处理方，包括处理目的、区域、保存、训练政策、删除能力
和合同依据；未配置的 Provider 不得列为已处理成功。

## 5. 数据主体和租户生命周期

管理员可按权限查询、导出、更正业务配置并发起删除。导出必须脱敏、加密、限时、审计并
绑定 hash；删除按数据库、对象存储和 Provider 三段 receipt 收敛，remaining 不为0时租户
不能标记 deleted。法定保留、争议冻结和不可变审计应在正式 DPA 中明确。

## 6. 安全与泄露响应

访问采用最小权限、forced RLS、短期 route/Worker ticket、密钥轮换和可追溯审计。疑似泄露
立即进入事件分级、证据保全、隔离、影响租户识别、法务评估、通知和复盘流程；通知时限由
适用法律和已签合同确定，模板不预设数字。
