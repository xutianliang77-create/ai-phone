## P3：新候选准备

1. 先解决/明确自动语种首发范围。当前仅固定中英有接线，`auto`不是已完成功能。继续实现与实测或经确认延期，不偷偷删除入口、换模型或降低质量标准。
2. 只读核对已有真实Apple月SKU、CNY10价格点、一周免费试用和资格、订阅组及旧合法购买兼容。可复用合格既有配置；创建商品/改价/改权限另审。不做模型对比。
3. 固定新的deployment，核对独立的Apple登录、App Store Server API、许可签名用途；App仅固定许可公钥。配置空缺保持关闭，不使用本轮fixture Key/SKU。新建/轮换真实Key及外部权限须具体批准。
4. 按 `CONFIGURATION_CONTRACT.json` 绑定Dart、原生Info和Worker。默认固定中文→英文；核对32/96/640ms、16kHz和VAD参数，保留显式覆盖及原生回读不一致拒用。默认不自动下载资源。
5. 新源清单与新构建号，完成完整iOS目标链接、既有签名材料核对、签名QA包和包内资源检查；系统资源单列，旧2026102604不能改标签复用。开发签名不冒充App Store分发资格。
6. 输出精确候选SHA、最小迁移与关闭部署方案、保数据安装方案、测试范围/窗口/费用和回滚点。P1/P2通过不自动放行部署或安装。

## P4：分步另审执行

- 关闭部署：仅新Worker/D1及控制secret/文档；最小兼容表＋新订阅/许可表，初始无已购权益。核对版本、关闭状态、旧推理路径404及备份恢复点。不能恢复已删旧账、未知占位或历史队列。
- 保数据安装：稳定备份→精确覆盖→账号命名空间、原记录、配置与资源回读。未登录新部署不暗迁旧凭据/记录。不得清手机来模拟干净安装。
- 真实Apple/设备最小验证：单独确认沙盒账号、商品、App Attest、系统资源准备、设备时间和QA绝对窗口。先验证真实控制链和固定中英短句，再进入长测。无充值/授额/自动续窗；沙盒交易也需明确测试批准。
