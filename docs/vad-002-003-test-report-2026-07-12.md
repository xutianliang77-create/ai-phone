## 2. OPT-VAD-002 故障注入

- 正常生产 health：`vadProvider=marblenet`、`vadThreshold=0.5`。
- 模型 SHA-256：`902bd89d8dec3dc42659d7f43abc6e75fccc987bbd7fbc92f5302b034cb3a531`，当前 health 不返回该 fingerprint。
- 模型或预处理资产缺失：成功退回 RMS，语音仍判为 voiced；Provider 只显示 `rms`，无法区分主动配置 RMS 与故障降级。
- ONNX 运行时异常：首次异常后切为 `rms_fallback`，后续请求继续使用 RMS。
- ASR 连续性：注入 ONNX 异常后，Qwen3 Engine 的隔离回归仍输出“RMS降级后ASR继续工作。”，endpointReason 为 `silence`。
- 最新真实 session 诊断只包含音频帧和 speaker turn 聚合；没有 VAD Provider、阈值、speech ratio、fallback 次数/原因和 fingerprint，segment 级 endpointReason 也未在详情中呈现。
- 自动化：ASR VAD/route 定向测试 `14 passed`。

### 必须开发

1. VAD Provider 提供只读 diagnostics snapshot：provider、configuredProvider、threshold、fallbackCount、fallbackReason、probability min/max/mean、speechFrameRatio、modelFingerprint。
2. 缺资产降级必须标记为 `rms_fallback`，不能与主动配置 `rms` 混同。
3. Gateway/API 按 session 保存白名单摘要；不保存逐帧概率或原始 PCM。
4. health 暴露当前 Provider、configured Provider、fingerprint 和累计 fallback 状态，并配置告警。

## 3. OPT-VAD-003 四模式基线

固定语料：`/data/models/translation-model-eval/eval/vad-opt-002-003/zh-smoke.wav`。PSTN 样本执行 `24k -> 8k -> 24k`，模拟窄带媒体进入 ASR 前的重采样。

| 模式 | mode 传入 ASR | 额外注入静音 | endpoint | 转写结果 |
| --- | --- | ---: | --- | --- |
| conversation | 否 | 580ms | silence | 有结果 |
| listening | 否 | 580ms | silence | 有结果 |
| call_link | 否 | 580ms | silence | 有结果 |
| pstn | 否 | 580ms | silence | 有结果 |

语料尾部已有约 `520ms` 被 MarbleNet 判为非语音，因此 `520 + 580 = 1100ms` 后四种模式同时触发。窄带样本仍可转写，说明基础连续性可用；但四种结果完全一致，不能证明模式策略。

### 必须开发

1. contracts、Gateway HTTP ASR 请求和 ASR session state 增加 `mode`，仅允许 `conversation/listening/call_link/pstn`。
2. 为四种模式建立独立 endpoint policy，不依赖进程级全局环境变量切换。
3. 每个 session 冻结 policy fingerprint，切换模式不能污染其他并发 session。
4. PSTN 在 Bridge/Worker 明确完成 8k 到 ASR 输入采样率转换，并记录源采样率和重采样策略。
5. 完成模式固定语料、延迟、误切、尾句和并发隔离回归后再验收。
